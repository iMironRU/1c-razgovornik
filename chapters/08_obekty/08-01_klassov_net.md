# § 8.1. Классов нет, а объекты есть

Написать `Класс Клиент` в 1С нельзя. Ни ключевого слова, ни синтаксиса, ни способа обойти: определить свой тип средствами встроенного языка не получится.

При этом объектов в системе полно, и у них есть и методы, и свойства, и события. Противоречия тут нет — просто классы создаёт не язык, а **конфигуратор**.

Справочник «Номенклатура» в дереве конфигурации устроен так:

| ветвь дерева | чем оказывается в коде |
|---|---|
| реквизиты | свойства объекта |
| табличные части | вложенные коллекции |
| модуль объекта | методы и обработчики событий |
| модуль менеджера | то, что в других языках было бы статикой |

Заводя справочник, вы порождаете новый тип — точнее, сразу семейство:
`СправочникСсылка.Номенклатура`, `СправочникОбъект.Номенклатура`,
`СправочникМенеджер.Номенклатура` и ещё несколько. Просто делаете это мышью в дереве,
а не текстом в файле. Зачем типов несколько, разберём в следующем параграфе — там
лежит главное отличие этой главы.

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| где объявляется тип | в дереве конфигурации | `class` в коде | `class` в коде | `class` в коде |
| наследование | нет; типы порождаются от шаблонов платформы | множественное | прототипное | одиночное + интерфейсы |
| свой базовый тип | нельзя | можно | можно | можно |
| методы экземпляра | модуль объекта | тело класса | тело класса | тело класса |
| статические методы | модуль менеджера | `@staticmethod` | `static` | `static` |

Наследования в привычном смысле нет вовсе. Ваш справочник не «наследник справочника»: платформа порождает его типы по своему шаблону, и продолжить цепочку нельзя. Построить иерархию «Товар» → «Весовой товар» не выйдет.

> Это опять «нет у вас, есть у платформы». Классы в системе существуют, порождать их вы можете, а вот **определять новые базовые типы** — нет: набор родителей закрыт, и в нём справочники, документы, регистры и прочие объекты конфигурации.

**Ловушки при переходе:**

*Из Python в 1С.* Привычка «сделаю класс на пять строк для удобства» не переносится. Для мелких структур данных здесь берут `Структуру`, для поведения — общий модуль с функциями.

*Из C# в 1С.* Интерфейсов нет, абстрактных классов нет, полиморфизма через наследование нет. Общее поведение выносят в общий модуль и вызывают оттуда.

*Из JavaScript в 1С.* Прототипов нет и объект на ходу не соберёшь: `{ имя: "Иван" }` превращается в `Новый Структура("Имя", "Иван")`, и методов у него не будет.

*Из 1С наружу.* Первое, к чему придётся привыкнуть, — что тип объявляется текстом и живёт в файле рядом с кодом, а не в дереве.
