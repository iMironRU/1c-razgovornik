# § 8.2. Ссылка и объект: различение, которого нет больше нигде

Самый важный параграф главы, и аналога у него нет ни в Python, ни в JavaScript, ни в C#. В этих языках объект один: взяли переменную, прочитали поле, изменили поле, сохранили. Здесь у одной и той же сущности **два разных типа**.

```bsl,платформа
// Ссылка — лёгкая, только адрес
СсылкаНаТовар = Справочники.Номенклатура.НайтиПоКоду("00042");
Сообщить(СсылкаНаТовар.Наименование);        // читать через ссылку можно

// Объект — тяжёлый, его можно менять и записывать
Товар = СсылкаНаТовар.ПолучитьОбъект();
Товар.Наименование = "Ручка синяя";
Товар.Записать();
```

| | ссылка | объект |
|---|---|---|
| что это | адрес записи в базе | загруженная запись целиком |
| чтение свойств | да, платформа подтянет из базы | да, всё уже в памяти |
| изменение | нельзя | можно |
| запись | нельзя | `Записать()` |
| хранится в реквизитах | да | нет |
| стоимость | почти ничего | чтение всей записи |

Правило перехода между ними простое: `Ссылка.ПолучитьОбъект()` вниз, `Объект.Ссылка` обратно.

## Зачем так сделано

Затем, что ссылок в системе тысячи, а объектов — единицы. Каждая строка документа хранит ссылку на товар; загружать при этом весь товар с реквизитами и табличными частями было бы разорительно. Ссылка — это указатель, который умеет по требованию подтянуть нужное поле.

Ближайшее, что можно вспомнить снаружи, — ленивая загрузка в ORM: `Django` с его `select_related`, `Entity Framework` с прокси-объектами. Но там это оптимизация, спрятанная библиотекой, а здесь — два разных типа в системе типов, и путать их не даст платформа.

> Практическое следствие, на котором спотыкаются все: **через ссылку изменить ничего нельзя**. Попытка присвоить свойство ссылке — ошибка. Увидели в чужом коде `ПолучитьОбъект()` — значит, дальше будут менять и записывать.

**Ловушки при переходе:**

*Из Python в 1С.* Привычка «получил объект — меняю» приводит к ошибке на первой же попытке: сначала надо понять, что у вас в руках.

*Из C# в 1С.* Ближе всего аналогия с прокси в Entity Framework, но там прокси притворяется объектом, а здесь ссылка объектом быть не притворяется — и это честнее.

*Из JavaScript в 1С.* Ссылка — не «объект без методов». Это отдельный тип со своим набором операций, и сравнение ссылок работает так, как вы ожидаете от идентификаторов.

*Из 1С наружу.* Различение исчезнет, и вместе с ним пропадёт дисциплина: снаружи ничто не помешает случайно загрузить тысячу объектов в цикле.
