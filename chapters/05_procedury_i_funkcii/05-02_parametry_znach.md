# § 5.2. Параметры: по ссылке, пока не сказано иначе

Здесь самая дорогая ловушка перехода, и стоит она дороже всех прочих в книге.

**В 1С параметр по умолчанию передаётся по ссылке.** Присвоили внутри процедуры — изменилась переменная у вызывающего. Для чисел, строк, дат и булева тоже: это не «объекты по ссылке, примитивы по значению», как в Python или JavaScript. Здесь по ссылке всё.

```bsl,песочница
Процедура Удвоить(Число)
    Число = Число * 2;
КонецПроцедуры

Цена = 100;
Удвоить(Цена);
Сообщить(Цена);        // 200 — переменная снаружи изменилась
```

Чтобы этого не происходило, параметр помечают словом `Знач`:

```bsl,песочница
Процедура УдвоитьБезопасно(Знач Число)
    Число = Число * 2;
КонецПроцедуры

Цена = 100;
УдвоитьБезопасно(Цена);
Сообщить(Цена);        // 100 — снаружи ничего не изменилось
```

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| по умолчанию | по ссылке | по значению ссылки | по значению ссылки | по значению |
| явно по значению | `Знач Х` | — | — | по умолчанию |
| явно по ссылке | по умолчанию | — | — | `ref Х` / `out Х` |

Ближайший родственник здесь — C# с его `ref`, но с перевёрнутой умолчательной. В Python и JavaScript такого различения нет вовсе: там всегда передаётся значение ссылки, и присваивание параметру никогда не видно снаружи.

> `Знач` защищает **переменную**, а не то, что в ней лежит. Если параметр — массив или структура, `Знач` копирует ссылку на объект: присвоить параметру новый массив не выйдет, а добавить элемент в старый — выйдет, и вызывающий это увидит.

```bsl,песочница
Процедура Испортить(Знач Список)
    Список.Добавить("лишнее");        // сработает, снаружи видно
    Список = Новый Массив;            // а это — нет, снаружи не видно
КонецПроцедуры

Товары = Новый Массив;
Товары.Добавить("Ручка");
Испортить(Товары);
Сообщить(Товары.Количество());        // 2
```

Вот в этом месте Python и JavaScript ведут себя точно так же — привычка сработает правильно. Расходятся языки только на примитивах.

**Ловушки при переходе:**

*Из Python в 1С.* Привычка «функция не может испортить мои числа и строки» неверна. Процедура, принявшая `Итого`, спокойно перезапишет его у вас. Если пишете процедуру, которая не должна ничего менять снаружи, — ставьте `Знач` на все входные параметры.

*Из C# в 1С.* Умолчание перевёрнуто: там `ref` надо просить, здесь надо просить `Знач`, чтобы его не было.

*Из JavaScript в 1С.* Ваша привычка мутировать переданный объект сработает и здесь — и это единственная часть, где всё как дома.

*Из 1С наружу.* Приём «передать переменную, чтобы процедура её заполнила» в Python и JavaScript не работает: возвращайте значение или структуру с несколькими значениями.
