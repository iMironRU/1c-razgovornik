# § 5.6. Обработчики событий: сигнатуру пишете не вы

Большая часть кода в живой конфигурации — процедуры, которых никто не вызывает. Их вызывает платформа, когда происходит событие: документ проводится, форма открывается, пользователь меняет поле.

```bsl,платформа
Процедура ОбработкаПроведения(Отказ, Режим)
    // Отказ и Режим пришли от платформы.
    // Присвоив Отказ = Истина, мы отменяем проведение.
КонецПроцедуры

Процедура ПриИзменении(Элемент)
    // Элемент — то поле формы, которое изменил пользователь
КонецПроцедуры
```

Особенность в том, что **имя и список параметров задаёт платформа**. Их нельзя выбрать, сократить или переставить: обработчик узнаётся по точному совпадению сигнатуры. Ошиблись в имени — процедура просто не вызовется, и ошибки не будет, потому что с точки зрения компилятора это обычный неиспользуемый метод.

Обработчики и есть та причина, по которой параметры в 1С передаются по ссылке. Платформа передаёт `Отказ`, ваш код присваивает ему `Истина`, платформа читает результат — механизм, который без передачи по ссылке не работал бы.

Прямого аналога у этой конструкции нет ни в одном из трёх языков.

| | как выглядит |
|---|---|
| Python | декоратор или явная подписка: `button.on_click(handler)` |
| JavaScript | `addEventListener("click", handler)` |
| C# | `button.Click += Handler;` — событие и делегат |
| 1С | процедура с предопределённым именем в нужном модуле |

Разница принципиальная: в трёх языках вы **подписываете** свою функцию на событие — то есть где-то есть строка кода, которая это делает, и её видно. В 1С подписки нет. Связь между событием и обработчиком не записана нигде: она возникает из того, что метод назван так, как ожидает платформа.

> Отсюда практическое следствие для чтения чужого кода: увидев процедуру, которую никто не вызывает, не спешите считать её мёртвой. Сверьтесь со списком событий объекта — скорее всего, это обработчик.

**Ловушки при переходе:**

*Из JavaScript в 1С.* Искать `addEventListener` бесполезно. Обработчик заводится через палитру свойств объекта, и конфигуратор сам вставляет заготовку процедуры с правильным именем — писать её руками не нужно и опасно.

*Из C# в 1С.* Делегатов нет, подписки нет, `+=` нет. Событие не объект, на него нельзя сослаться.

*Из Python в 1С.* Ближайшая знакомая вещь — методы вроде `__init__`, которые вызываются по имени, а не по вызову. Здесь так устроен весь прикладной код.

*Из 1С наружу.* Привычка «назвал правильно — заработает» ломается сразу: снаружи подписку надо написать явно, иначе не вызовется ничего.
