# § 5.6. Обработчики событий — это хуки

Откройте любой модуль живой конфигурации, и большинство процедур в нём окажется без единого вызова. Найти, кто их запускает, не выйдет: их запускает платформа, когда происходит событие — документ проводится, форма открывается, пользователь меняет поле.

Знакомое слово для этого — **хук**. Место, где чужая программа прерывает свою работу и передаёт управление вашей.

```bsl,платформа
Процедура ОбработкаПроведения(Отказ, Режим)
    // Отказ и Режим пришли от платформы.
    // Присвоив Отказ = Истина, мы отменяем проведение.
КонецПроцедуры

Процедура ПриИзменении(Элемент)
    // Элемент — то поле формы, которое изменил пользователь
КонецПроцедуры
```

## Почему это устроено так

Потому что 1С — платформа, а не библиотека. Разница определяющая.

Библиотеку вы вызываете: главный цикл ваш, вы решаете, что и когда происходит. Платформа вызывает вас: главный цикл её, а ваш код живёт в промежутках, которые она оставила. Это инверсия управления, и вы её уже встречали — в жизненном цикле React-компонента, в сигналах Django, в событиях страницы ASP.NET.

Отсюда и **имя, и список параметров задаёт платформа**. Их нельзя выбрать, сократить или переставить: хук узнаётся по точному совпадению сигнатуры. Обычно заготовку вставляет конфигуратор, и ошибиться негде, — но стоит переименовать процедуру руками, и она замолчит. Ошибки при этом не будет: с точки зрения компилятора это обычный неиспользуемый метод.

Отсюда же и передача параметров по ссылке, с которой началась эта глава. Платформа передаёт `Отказ`, ваш код присваивает ему `Истина`, платформа читает результат — механизм, который без передачи по ссылке не работал бы.

## Как подключается хук

| | как связывается |
|---|---|
| Python, Django | явная подписка: декоратор `@receiver` |
| JavaScript | явная подписка: `addEventListener("click", handler)` |
| C#, событие | явная подписка: `button.Click += Handler;` |
| React, класс | по имени: `componentDidMount` |
| ASP.NET WebForms | по имени: `Page_Load` |
| 1С | по имени: `ПриОткрытии`, `ОбработкаПроведения` |

Аналог, как видите, есть — но не в языке, а во фреймворках, и в тех из них, что постарше. В языке ни Python, ни JavaScript, ни C# такой связи не знают: там подписка — это строка кода, и её видно.

В 1С строки подписки нет. Связь между хуком и событием всё-таки записана — но не в коде, а в свойствах объекта или формы, то есть в метаданных. Читая модуль, вы её не увидите; смотреть надо палитру свойств.

## Когда подписка всё же есть

Одно исключение стоит знать заранее, иначе оно собьёт с толку. У событий прикладных объектов есть отдельный механизм — **подписка на событие**, и это самостоятельный объект в дереве метаданных.

```текст
Дерево конфигурации
├── Документы
├── Подписки на события     ← сюда
│   └── ПроверкаПередЗаписью
│         Источник:   ДокументОбъект.РеализацияТоваров
│         Событие:    ПередЗаписью
│         Обработчик: ОбщийМодуль.Проверки.ПередЗаписью
└── ...
```

Здесь связь объявлена явно: вот источник, вот событие, вот метод-обработчик в общем модуле. Это ближе всего к тому, что вы называете подпиской, — только пишется она не строкой кода, а объектом конфигурации.

Разница практическая. Хук в модуле самого объекта видит только этот объект; подписка позволяет повесить один обработчик сразу на несколько видов документов и держать его в общем модуле.

> Практическое следствие для чтения чужого кода: увидев процедуру, которую никто не вызывает, не спешите считать её мёртвой. Сверьтесь со списком событий объекта и с ветвью «Подписки на события» — скорее всего, это хук.

**Ловушки при переходе:**

*Из JavaScript в 1С.* Искать `addEventListener` бесполезно. Хук заводится через палитру свойств объекта, и конфигуратор сам вставляет заготовку с правильным именем — писать её руками не нужно и опасно.

*Из C# в 1С.* Делегатов нет, подписки нет, `+=` нет. Событие не объект, на него нельзя сослаться и его нельзя передать.

*Из Python в 1С.* Ближайшая знакомая вещь — методы вроде `__init__`, которые вызываются по имени, а не по вызову. Здесь так устроен весь прикладной код.

*Из 1С наружу.* Привычка «назвал правильно — заработает» ломается сразу: снаружи подписку надо написать явно, иначе не вызовется ничего.
