# § 5.4. `Экспорт` — вся модель видимости

Модификаторов доступа в 1С нет. Ни `public`, ни `private`, ни `protected`, ни соглашения о подчёркивании. Есть одно слово в конце строки объявления:

```bsl,песочница
// Видна снаружи модуля
Функция ПосчитатьСкидку(Сумма) Экспорт
    Возврат Сумма * 0.1;
КонецФункции

// Видна только внутри этого модуля
Функция ОкруглитьПоПравилам(Значение)
    Возврат Окр(Значение, 2);
КонецФункции
```

Есть `Экспорт` — метод доступен извне. Нет — метод внутренний. Третьего состояния не существует.

Снаружи экспортный метод вызывается через имя модуля:

```bsl,платформа
Скидка = РаботаСоСкидками.ПосчитатьСкидку(1000);
```

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| публичный | `Экспорт` | по умолчанию | `export` | `public` |
| приватный | без `Экспорт` | `_имя` (соглашение) | без `export` | `private` |
| промежуточные уровни | нет | нет | нет | `protected`, `internal` |

Ближе всего JavaScript с его `export`: там тоже видимость решается на уровне модуля, а не класса, и по умолчанию всё закрыто. Разница в том, что в JavaScript экспорт можно написать отдельной строкой в конце файла, а в 1С он прирастает к объявлению.

> В 1С нет уровня «доступно наследникам» и «доступно внутри сборки». Наследования у модулей нет, сборок нет — значит, и градаций между «моё» и «всехное» не бывает.

**Ловушки при переходе:**

*Из Python в 1С.* Подчёркивание в начале имени здесь ничего не значит, это просто буква. Единственный признак приватности — отсутствие `Экспорт`, и он не соглашение, а проверка компилятора: вызвать неэкспортный метод снаружи не выйдет.

*Из C# в 1С.* `protected` и `internal` заменить нечем. Если механизм должен быть виден части системы, но не всей, — в языке средств для этого нет; вопрос решается расположением кода и именованием, то есть договорённостями команды.

*Из 1С наружу.* Слово `Экспорт` не переводится напрямую: в Python приватности нет вообще, там всё публично, а `_имя` — просьба, а не запрет.
