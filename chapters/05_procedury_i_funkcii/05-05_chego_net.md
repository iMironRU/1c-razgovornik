# § 5.5. Чего нет у вас — и что при этом есть у платформы

Это самый короткий способ сэкономить полдня: перечислить приёмы, которые вы будете искать и не найдёте. Но перед списком — важная оговорка, без которой список вводит в заблуждение.

## Кто чего не может

Почти каждое «в 1С нельзя» из этой главы означает «нельзя **вам**», а не «в системе такого не бывает».

Возьмите перегрузку. Написать два метода с одним именем в модуле нельзя — компилятор не даст. А вот сама платформа перегруженными методами пользуется свободно:

```bsl,песочница
А = Новый Массив;              // без параметров
Б = Новый Массив(10);          // один параметр — размер
В = Новый Массив(3, 4);        // два параметра — двумерный
```

Три разных вызова одного конструктора, с разным числом параметров и разным смыслом. Синтакс-помощник называет это **вариантами синтаксиса** и показывает их для метода до восьми штук.

Не всякая гибкость платформы — перегрузка, и различать стоит. Когда `Формат()` принимает и число, и дату, — это не перегрузка, а один метод с параметром произвольного типа: язык динамический, тип аргумента вообще нигде не объявлен. Перегрузка — это когда **разное число параметров** означает разные операции, как у `Новый Массив`.

Причина проста и объясняет многое в этой книге. **Встроенный язык — не тот язык, на котором написана платформа.** Платформа написана на C++, а встроенный язык — то, что она предоставляет прикладному разработчику. Ограничения прикладного языка на её собственный API не распространяются, и наоборот: увидев в синтакс-помощнике восемь вариантов вызова, не считайте, что так можно и у себя.

> Держите это различение всю книгу: «нет в 1С» почти всегда значит «нет в прикладном языке». Платформа умеет больше, чем разрешает.

## Чего нет у вас

**Перегрузки нет.** Разные случаи разводят значениями по умолчанию или разными именами: `ПрочитатьПоСсылке`, `ПрочитатьПоКоду`.

**Функция не значение.** Её нельзя присвоить переменной, передать параметром, вернуть из другой функции, положить в массив.

**Лямбд и замыканий нет.** Ни `lambda`, ни стрелочных функций, ни захвата переменных из окружения.

Отсюда выпадает целый пласт приёмов:

| приём | Python | JavaScript | в 1С |
|---|---|---|---|
| функция как аргумент | `map(f, xs)` | `xs.map(f)` | явный цикл |
| фильтрация | `filter` | `.filter()` | явный цикл |
| свёртка | `reduce` | `.reduce()` | явный цикл с накопителем |
| сортировка по ключу | `key=` | `.sort(cmp)` | `Сортировать("Колонка Убыв")` у таблицы |
| колбэк | функция | функция | `ОписаниеОповещения` |
| декоратор | `@` | обёртка | нет |
| частичное применение | `partial` | замыкание | нет |

Единственное, что отдалённо заменяет передачу функции, — **вызов по имени**: имя метода передаётся строкой, а платформа его находит.

```bsl,платформа
// Отложенный вызов: имя обработчика — строка
Оповещение = Новый ОписаниеОповещения("ПослеЗакрытия", ЭтотОбъект);
ПоказатьВопрос(Оповещение, "Продолжить?", РежимДиалогаВопрос.ДаНет);
```

Это не функция как значение: передаётся не метод, а его имя и место, где искать. Компилятор такую строку не проверяет — опечатка станет ошибкой времени выполнения.

**Ловушки при переходе:**

*Из Python в 1С.* Первое, чего будет не хватать, — `map` и `filter`. Пишите цикл и не ищите обхода: его нет, а попытка изобрести через `Выполнить()` сделает код хуже.

*Из JavaScript в 1С.* Колбэк существует, но выглядит как строка с именем. Проверка опечатки — только запуском.

*Из C# в 1С.* Ни LINQ, ни делегатов, ни перегрузки в вашем коде. При этом методы платформы перегружены — не удивляйтесь несимметричности.

*Из 1С наружу.* Привычка писать цикл на всё подряд будет читаться как неумение: снаружи тот же перебор ожидают увидеть одной строкой.
