# § 7.3. `Асинх`, `Ждать` и `Обещание`

С версии **8.3.18** во встроенном языке появилось то, что вы узнаете с первого взгляда:

```bsl,платформа
Асинх Процедура ПровестиДокумент(Команда)
    Ответ = Ждать ВопросАсинх("Провести документ?",
        РежимДиалогаВопрос.ДаНет);
    Если Ответ = КодВозвратаДиалога.Да Тогда
        // продолжение здесь же, в той же процедуре
    КонецЕсли;
КонецПроцедуры
```

Две процедуры из прошлого параграфа схлопнулись в одну. Логика снова читается сверху вниз.

Правила, по которым это работает, укладываются в четыре пункта.

**`Асинх` — модификатор процедуры или функции.** Ставится перед словом `Процедура` или `Функция`.

**`Асинх`-функция всегда возвращает `Обещание`** — объект с тремя состояниями: ожидание, успех, ошибка. То, что вы написали в `Возврат`, окажется завёрнутым в него.

**`Ждать` работает только внутри `Асинх`.** Снаружи — синтаксическая ошибка, ровно как `await` вне `async` в JavaScript.

**Старые методы получили двойников с суффиксом `Асинх`.** `Вопрос` → `ВопросАсинх`, и так по всему списку; двойник возвращает `Обещание`.

| | 1С | JavaScript | Python | C# |
|---|---|---|---|---|
| модификатор | `Асинх` | `async` | `async def` | `async` |
| ожидание | `Ждать` | `await` | `await` | `await` |
| тип результата | `Обещание` | `Promise` | корутина | `Task` |
| создать свой вручную | нельзя | `new Promise(...)` | можно | `TaskCompletionSource` |

Последняя строка — единственная, где сходство ломается. **Создать `Обещание` через `Новый` нельзя.** Оно появляется только как результат асинхронной функции: либо метода платформы с суффиксом `Асинх`, либо вашей собственной, помеченной `Асинх`. Обернуть в него что-то своё — например, ожидание внешнего события — не выйдет.

> И одна тонкость, которая аукнется тем, кто читал главу про процедуры. У `Асинх` процедур и функций **все параметры передаются по значению**, слово `Знач` там подразумевается само. Умолчание всего языка на асинхронных методах перевёрнуто, и предупреждения об этом вы нигде не увидите.

**Ловушки при переходе:**

*Из JavaScript в 1С.* Синтаксис почти ваш, но `new Promise` заменить нечем: обернуть произвольное событие в ожидаемый объект нельзя.

*Из C# в 1С.* `TaskCompletionSource` тоже нет. И `Обещание` — не `Task`: за ним не стоит ни поток, ни пул.

*Из Python в 1С.* `Ждать` без `Асинх` не работает — правило то же, что у вас. А вот собрать свою корутину не получится.

*Из 1С наружу.* Привычку «`Асинх` — значит параметры по значению» придётся забыть: снаружи модификатор на способ передачи не влияет никак.
