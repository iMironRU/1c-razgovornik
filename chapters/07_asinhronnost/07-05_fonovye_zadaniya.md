# § 7.5. Фоновые задания: вот где параллелизм

То, что вы искали в предыдущем параграфе, называется здесь по-другому и живёт не в языке, а в платформе.

**Фоновое задание** — это выполнение процедуры в отдельном сеансе на сервере, независимо от того, что делает пользователь. Запустили, получили идентификатор, продолжили работу; результат заберёте потом.

```bsl,платформа
Задание = ФоновыеЗадания.Выполнить(
    "Отчёты.Посчитать",   // имя метода строкой
    Параметры,            // массив параметров
    "Ключ",
    "Пересчёт за год");   // имя для журнала

// код продолжается сразу
```

Три вещи, которые бросаются в глаза человеку со стороны.

**Метод передаётся строкой.** Опять по имени, как в колбэках, и опять без проверки при написании.

**Параметры уезжают в другой сеанс.** Передать туда объект, живущий в памяти клиента, нельзя: сериализуется только то, что платформа умеет упаковать. Замыкание не поедет — их и нет.

**Результат не возвращается напрямую.** Забирают его через временное хранилище или регистр; задание само по себе значения не отдаёт.

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| механизм | фоновое задание | процесс или пул | воркер | поток или `Task` |
| где выполняется | отдельный сеанс на сервере | процесс той же машины | отдельный поток браузера | пул потоков |
| что передаётся | сериализуемые параметры | пикл или аргументы | сообщение | ссылки на объекты |
| общая память | нет | нет у процессов | нет | есть |

Ближайший родственник — не поток, а **процесс**: отдельный сеанс, своя память, обмен только через сериализацию. Кто работал с `multiprocessing` в Python или с воркерами в браузере, узнает и ограничения, и способ обходиться.

> Итог главы одной строкой: `Асинх` — чтобы интерфейс не замирал; фоновое задание — чтобы считать, пока пользователь занят другим. Первое живёт в языке, второе в платформе, и путать их дорого.

**Ловушки при переходе:**

*Из Python в 1С.* Это ближе к `multiprocessing`, чем к `threading`: разделяемой памяти нет, всё через сериализацию.

*Из C# в 1С.* Забудьте про общий объект между потоками — сеансы разные, и объект туда не передать.

*Из JavaScript в 1С.* Похоже на Web Worker: обмен сообщениями, ничего общего в памяти. Только запускается на сервере, а не в браузере.

*Из 1С наружу.* Привычка «всё тяжёлое — в фоновое задание» переносится хорошо, но снаружи выбор шире: там между «в этом же потоке» и «в отдельном процессе» есть промежуточные варианты, которых здесь нет.
