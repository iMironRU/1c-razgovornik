# § 6.3. `ВызватьИсключение`: бросать научились раньше, чем ловить

Простая форма выглядит как везде:

```bsl,песочница
Функция Разделить(Делимое, Делитель)
    Если Делитель = 0 Тогда
        ВызватьИсключение "Деление на ноль недопустимо";
    КонецЕсли;
    Возврат Делимое / Делитель;
КонецФункции

Попытка
    Сообщить(Разделить(10, 0));
Исключение
    Сообщить(ОписаниеОшибки());
КонецПопытки;
```

Бросается строка. Своего типа исключения объявить нельзя: класса, от которого можно унаследоваться, в языке нет.

Долгое время на этом всё и кончалось, и книги про 1С писали «исключение — это просто текст». С версии **8.3.21** это уже неправда: у оператора появилась развёрнутая форма.

```bsl,набросок
ВызватьИсключение (
    "Не удалось провести документ",   // текст для пользователя
    КатегорияОшибки.<...>,            // категория
    "DOC_POST_FAILED",                // код для классификации
    "Документ №14 от 03.03",          // дополнительный контекст
    ИнформацияОбОшибке()              // причина: то, что поймали выше
);
```

Последний параметр важнее прочих. Он строит **цепочку причин**: внешнее исключение говорит пользователю, что не получилось, а внутреннее сохраняет исходную техническую ошибку. Ровно то, для чего в Python пишут `raise ... from e`, а в C# передают `innerException`.

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| бросить | `ВызватьИсключение "текст"` | `raise ValueError("текст")` | `throw new Error("текст")` | `throw new Exception("текст")` |
| свой тип | нет | класс-наследник | класс-наследник | класс-наследник |
| код ошибки | параметр `Код` (8.3.21+) | поле класса | поле объекта | свойство |
| сохранить причину | параметр `Причина` (8.3.21+) | `raise … from e` | `{ cause: e }` | `innerException` |
| пробросить дальше | `ВызватьИсключение;` без параметров | `raise` | `throw` | `throw;` |

> Асимметрия бросается в глаза: **описать** ошибку платформа даёт подробно, а **поймать** её выборочно — нет. Категорию и код можно задать, но перехватить только исключения нужной категории всё равно нельзя: разбирать придётся уже внутри обработчика.

**Ловушки при переходе:**

*Из Python в 1С.* `raise ValueError(...)` не переводится: тип придётся кодировать строкой в параметре `Код` и разбирать её вручную.

*Из C# в 1С.* Ближайший знакомый приём — `innerException`, и он здесь есть под именем `Причина`. Только доступен с 8.3.21, а в конфигурациях постарше вы его не встретите.

*Из JavaScript в 1С.* `throw` без аргумента у вас недопустим, а `ВызватьИсключение;` без параметров — штатный способ пробросить пойманное дальше.

*Из 1С наружу.* Привычка сообщать об ошибке одной строкой обеднит код: снаружи тип исключения — часть контракта функции, и по нему вызывающий решает, что делать.
