# § 6.1. Попытка, Исключение — и никакого `finally`

Конструкция знакомая с точностью до слов:

```bsl,песочница
Попытка
    Результат = 100 / 0;
Исключение
    Сообщить("Что-то пошло не так");
КонецПопытки;

Сообщить("Программа продолжает работу");
```

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| блок риска | `Попытка` | `try` | `try` | `try` |
| блок обработки | `Исключение` | `except` | `catch` | `catch` |
| закрытие | `КонецПопытки;` | отступ | `}` | `}` |
| «выполнить в любом случае» | **нет** | `finally` | `finally` | `finally` |

Первые три строки — косметика. Четвёртая — то, ради чего параграф написан.

## Чем заменяют `finally`

Гарантированного блока очистки в языке нет. Если ресурс нужно освободить в любом случае, освобождать приходится дважды — в успешной ветке и в обработчике:

```bsl,песочница
Соединение = "открыто";

Попытка
    Сообщить("Работаем: " + Соединение);
    ВызватьИсключение "сбой посередине";
    Соединение = "закрыто";              // в успешной ветке
Исключение
    Соединение = "закрыто";              // и здесь тоже
    Сообщить("Ошибка, но соединение закрыли");
КонецПопытки;

Сообщить("Соединение: " + Соединение);
```

Дублирование некрасивое, и обойти его нечем. Приём, который в 1С применяют вместо `finally`, — вынести очистку в отдельную процедуру и вызвать её из обеих веток: дублируется тогда одна строка, а не блок.

> Отсутствие `finally` — не мелочь стиля. Оно означает, что забыть освобождение можно ровно одним способом: дописать в блок `Попытка` ещё один `Возврат` и не заметить, что после него очистка не выполнится.

**Ловушки при переходе:**

*Из Python в 1С.* Кроме `finally` здесь нет и `with`: контекстных менеджеров в языке не существует, `__enter__` и `__exit__` заменить нечем.

*Из C# в 1С.* `using` тоже нет. Освобождение — руками, в обеих ветках.

*Из JavaScript в 1С.* Привычка обходиться `try/finally` без `catch` не сработает: блок `Исключение` обязателен, пустым его оставлять нельзя.

*Из 1С наружу.* Первое, что стоит перенять снаружи, — `finally`. Дублирование очистки, привычное здесь, там читается как ошибка.
