# § 6.5. Транзакции: конструкция, которой снаружи нет

Последний параграф главы — про то, чему аналога в Python, JavaScript и C# практически не найдётся. Не потому, что транзакций там нет: они есть, но живут в библиотеке работы с базой, а не в самом языке. В 1С работа с базой — часть платформы, и транзакция открывается тремя операторами.

```bsl,платформа
НачатьТранзакцию();
Попытка
    // изменяем данные
    Документ.Записать();
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;      // пробросить дальше
КонецПопытки;
```

Эти восемь строк — канонический шаблон, и написаны они так не из вкуса. Разберём, что здесь важно.

**Отмена не происходит сама.** Исключение транзакцию не откатывает — оно взводит служебный признак «запрет успешного завершения». Транзакция остаётся открытой, просто зафиксировать её уже нельзя. Настоящий откат случится только тогда, когда код дойдёт до `ОтменитьТранзакцию()`. Не дойдёт — она так и останется висеть.

**Отмена идёт первой.** Внутри обработчика сначала откат, и только потом всё остальное — запись в журнал, сообщение пользователю. Причина конкретная: пока активна транзакция, в которой уже случилось исключение, любое обращение к базе даёт ошибку «В этой транзакции уже происходили ошибки». Полезете в журнал до отката — потеряете исходную ошибку и получите вместо неё эту.

**Проброс обязателен.** `ВызватьИсключение;` без параметров передаёт пойманное наверх. Без него вызывающий код решит, что всё прошло успешно, — а данные не записаны.

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| где живёт | во встроенном языке | в библиотеке драйвера | в библиотеке | `TransactionScope`, ORM |
| откат при ошибке | руками | часто автоматически по выходу из `with` | зависит от библиотеки | автоматически по выходу из `using` |
| незакрытая транзакция | ломает последующие операции | закроется по выходу из блока | зависит | закроется по выходу из блока |

> В Python и C# транзакция закрывается сама на выходе из блока — потому что там есть `with` и `using`. В 1С нет ни того ни другого, и это ровно то же отсутствие `finally`, с которого началась глава. Здесь оно стоит дороже всего: забытый откат ломает не одну операцию, а всю дальнейшую работу сеанса.

**Ловушки при переходе:**

*Из Python в 1С.* `with connection.begin()` заменить нечем: шаблон из восьми строк придётся писать целиком каждый раз, и в нём легко забыть проброс.

*Из C# в 1С.* Ни `TransactionScope`, ни `using`. Откат — ваша забота, и порядок действий в обработчике важен.

*Из JavaScript в 1С.* Транзакция здесь не объект, который можно передать: это состояние сеанса, открытое оператором.

*Из 1С наружу.* Привычка писать откат руками не повредит, но окажется лишней: снаружи блок закроет транзакцию сам.
