# § 6.4. Что можно узнать о пойманном

Внутри блока `Исключение` доступны три функции, и путать их не стоит.

```bsl,песочница
Попытка
    ВызватьИсключение "Склад недоступен";
Исключение
    Сообщить(ОписаниеОшибки());              // короткий текст
    Ошибка = ИнформацияОбОшибке();           // объект с подробностями
    Сообщить(Ошибка.Описание);
КонецПопытки;
```

`ОписаниеОшибки()` отдаёт строку — это самый старый и самый простой способ. `ИнформацияОбОшибке()` отдаёт **объект**, и вот его вы и будете разбирать:

| свойство | что внутри |
|---|---|
| `Описание` | текст ошибки для пользователя |
| `ИмяМодуля` | полное имя модуля, где случилось |
| `НомерСтроки` | номер строки в этом модуле |
| `ИсходнаяСтрока` | сама строка кода, которая упала |
| `Причина` | вложенный объект того же типа — или `Неопределено` |
| `Код` | код классификации, если его задали (8.3.21+) |
| `ДополнительнаяИнформация` | произвольный контекст (8.3.21+) |

Три средних свойства — это то, что в других языках называют трассировкой стека. Только здесь она не список кадров, а одна точка: модуль, строка, текст строки.

## Цепочка причин заменяет стек

Полной трассировки в 1С нет. Вместо неё — `Причина`, и по ней можно спуститься к исходной ошибке:

```bsl,набросок
Ошибка = ИнформацияОбОшибке();
Пока Ошибка <> Неопределено Цикл
    Сообщить(Ошибка.ИмяМодуля + ":" + Ошибка.НомерСтроки
           + " — " + Ошибка.Описание);
    Ошибка = Ошибка.Причина;
КонецЦикла;
```

Цепочка бывает двух происхождений, и это стоит различать. Ошибки самой платформы приходят вложенными уже готовыми: верхняя описывает, что не получилось, самая глубокая — исходную причину. А вот в вашем коде цепочка появится только там, где при перебросе вы передали пойманное в параметр `Причина`. Не передали — цепочка обрывается на вас.

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| текст ошибки | `Описание` | `str(e)` | `e.message` | `e.Message` |
| где случилось | `ИмяМодуля`, `НомерСтроки` | traceback | `e.stack` | `e.StackTrace` |
| полный стек вызовов | нет | да | да | да |
| причина | `Причина` | `e.__cause__` | `e.cause` | `e.InnerException` |

> Отсутствие полного стека — самое ощутимое отличие в этой главе. Привычка «прочитать traceback и сразу увидеть, откуда пришли» не работает: видно только последнее место падения, а путь до него надо восстанавливать по цепочке причин, если её кто-то выстроил.

Для вывода пользователю есть ещё две функции — `КраткоеПредставлениеОшибки()` и `ПодробноеПредставлениеОшибки()`. Обе принимают объект информации об ошибке и собирают из него готовый текст: первая — короткий, вторая — со всеми подробностями и цепочкой.

**Ловушки при переходе:**

*Из Python в 1С.* `traceback.format_exc()` заменить нечем. Готовьтесь логировать `ИмяМодуля` и `НомерСтроки` руками — иначе через месяц по логу не восстановите, что произошло.

*Из C# в 1С.* `StackTrace` нет, `InnerException` есть под именем `Причина` — но только если кто-то потрудился её передать.

*Из JavaScript в 1С.* `e.stack` нет. Есть точка падения и, если повезёт, цепочка.

*Из 1С наружу.* Привычка вручную собирать текст ошибки из свойств пропадёт: снаружи `traceback` печатается сам и в разы подробнее.
