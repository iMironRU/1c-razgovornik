# § 6.2. Ловится всё сразу: фильтра по типу нет

Вторая привычка, которую придётся оставить у порога.

Во всех трёх языках сравнения обработчик можно сузить: перехватить только то исключение, с которым вы знаете, что делать, а остальные пропустить наверх. В 1С этого нет. Блок `Исключение` ловит **всё**, что случилось внутри `Попытки`, — и вашу ожидаемую ошибку связи, и опечатку в имени переменной.

```bsl,песочница
Попытка
    Сумма = "не число" + 10;          // ошибка приведения типа
Исключение
    // Сюда попадёт и она, и любая другая
    Сообщить("Поймали: " + ОписаниеОшибки());
КонецПопытки;
```

| | 1С | Python | JavaScript | C# |
|---|---|---|---|---|
| перехват по типу | нет | `except ValueError` | `if (e instanceof …)` | `catch (IOException e)` |
| несколько обработчиков | нет | несколько `except` | один `catch` + `if` | несколько `catch` |
| перехватить всё | по умолчанию | `except Exception` | `catch (e)` | `catch (Exception)` |

JavaScript тут ближе всех: там тоже один `catch`, и разбирать приходится внутри. Похожесть, впрочем, неполная. С версии 8.3.21 у ошибки в 1С есть и категория, и код — то есть разбирать можно не только текст. Чего нет, так это возможности **отфильтровать перехват**: даже зная категорию, вы всё равно поймаете сначала всё, а сортировать будете потом.

> Плата за это — известная: широкий `Исключение` глотает и те ошибки, которых вы не ждали. Опечатка в имени метода внутри `Попытки` не свалит программу, а тихо уйдёт в обработчик и будет выглядеть как «сервис недоступен».

## Как с этим живут

Правило простое и не 1С-специфичное — оно то же, что для `except Exception` в Python: **держите `Попытку` как можно короче**. В блоке риска — одна операция, которая действительно может отказать, а не двадцать строк логики.

```bsl,песочница
// Плохо: под защитой оказалась вся логика
Попытка
    Данные = ПолучитьДанные();
    Итог = Данные * 2;
    Сообщить(Итог);
Исключение
    Сообщить("Ошибка получения данных");   // а сломаться могло что угодно
КонецПопытки;

// Лучше: рискует только то, что рискует
Попытка
    Данные = ПолучитьДанные();
Исключение
    Сообщить("Ошибка получения данных");
    Возврат;
КонецПопытки;

Итог = Данные * 2;
Сообщить(Итог);

Функция ПолучитьДанные()
    Возврат 21;
КонецФункции
```

**Ловушки при переходе:**

*Из C# в 1С.* Привычка «поймаю `IOException`, остальное пусть летит выше» не переносится. Пропустить наверх можно только одним способом: поймать всё, разобраться и бросить заново.

*Из Python в 1С.* Никаких `except ValueError as e`. И иерархии исключений, по которой можно ловить целую ветку, тоже нет.

*Из JavaScript в 1С.* Один `catch` вам знаком — но `instanceof` здесь не на чем применить.

*Из 1С наружу.* Появится соблазн писать `except Exception` везде. Это работает, но снаружи считается плохим тоном: там принято ловить то, что ожидаешь.
